Before we start

Why this matters

A user types “abc” where your program expects a number. Should the whole program crash?

Without exception handling, yes: Java prints a stack trace and stops. With it, you can catch the problem, explain it to the user and carry on.

Java separates the code that does the work from the code that handles problems, and the compiler even forces you to deal with some kinds of failure.

What is an exception?

public class Crash {
    static int avg(int[] a) { return sum(a) / a.length; }
    static int sum(int[] a) { int s = 0; for (int x : a) s += x; return s; }
    public static void main(String[] args) {
        System.out.println(avg(new int[]{4, 6}));
        System.out.println(avg(new int[]{}));
        System.out.println("never printed");
    }
}
Output
5
Exception in thread "main" java.lang.ArithmeticException: / by zero
	at Crash.avg(Crash.java:2)
	at Crash.main(Crash.java:6)
  • An exception is an object that describes an error that happened while the program was running.
  • When it is thrown, normal execution stops and Java looks back through the call stack for a matching handler.
  • If no method handles it, the thread ends and the stack trace shows where it happened — read it from the top.

Concept 3 of 6

try, catch and finally

try {
    int n = Integer.parseInt(text);   // may throw
    System.out.println(100 / n);      // may throw
} catch (NumberFormatException e) {
    System.out.println("Not a number");
} catch (ArithmeticException e) {
    System.out.println("Cannot divide by zero");
} finally {
    System.out.println("done");       // always runs
}
  • try wraps code that may throw. The rest of the try block is skipped after an exception.
  • catch handles one type (and its subclasses). The first matching catch runs.
  • finally runs whether or not an exception occurred — even after return. Use it for clean-up.

Concept 4 of 6

Multiple catch clauses and multi-catch

try {
    ...
} catch (FileNotFoundException e) {    // most specific first
    System.out.println("Missing file");
} catch (IOException e) {              // then its superclass
    System.out.println("I/O problem");
} catch (NumberFormatException | ArithmeticException e) {
    System.out.println("Bad data: " + e.getMessage());
} catch (Exception e) {                // catch-all last
    e.printStackTrace();
}
  • Order catches from specific to general. A superclass catch before its subclass makes the later one unreachable — a compile error.
  • Multi-catch (A | B) shares one handler; A and B must not be related by inheritance.
  • Useful methods of every exception: getMessage(), toString(), printStackTrace().

Code example

Creating your own exceptions

class InsufficientFundsException extends Exception {     // checked
    private final double shortBy;
    InsufficientFundsException(double shortBy) {
        super("Insufficient funds: short by " + shortBy);
        this.shortBy = shortBy;
    }
    double getShortBy() { return shortBy; }
}
class Account {
    private double balance = 500;
    void withdraw(double amt) throws InsufficientFundsException {
        if (amt > balance) throw new InsufficientFundsException(amt - balance);
        balance -= amt;
        System.out.println("Withdrew " + amt + ", left " + balance);
    }
}
Account acc = new Account();
try {
    acc.withdraw(200);
    acc.withdraw(450);
    acc.withdraw(10);
} catch (InsufficientFundsException e) {
    System.out.println(e.getMessage());
}
Output
Withdrew 200.0, left 300.0
Insufficient funds: short by 150.0
  • Extend Exception for a checked exception, RuntimeException for an unchecked one.
  • Pass a message to super(msg); add fields for extra details.

Code example

try-with-resources

try (BufferedReader br = new BufferedReader(new FileReader("marks.txt"))) {
    String line;
    int total = 0;
    while ((line = br.readLine()) != null)
        total += Integer.parseInt(line.trim());
    System.out.println("Total = " + total);
} catch (FileNotFoundException e) {
    System.out.println("File missing: " + e.getMessage());
} catch (IOException | NumberFormatException e) {
    System.out.println("Bad data: " + e);
}
Output (marks.txt holds 78, 91 and 64)
Total = 233
  • Resources declared in try ( … ) are closed automatically at the end, in reverse order, even if an exception occurs.
  • Works with any class that implements AutoCloseable: files, sockets, database connections, Scanner.

ACDE. B is skipped; the catch handles the exception; finally always runs; the program continues.

static int readScore(Scanner in) {
    while (true) {
        try {
            return Integer.parseInt(in.nextLine().trim());

Summary

Summary

  • An exception is an object describing a run-time error; uncaught ones end the thread with a stack trace.
  • Checked exceptions must be caught or declared; unchecked (RuntimeException) and Errors need not be.
  • try runs risky code, the first matching catch handles it, finally always runs.
  • throw raises an exception object; throws declares what a method may pass on.
  • Custom exceptions extend Exception or RuntimeException; try-with-resources closes resources automatically.
